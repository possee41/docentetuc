# Automatización FDCI 1.2 (preparada, no activada)

Estado: **el `schedule` sigue comentado y no se desplegó nada**. Este documento describe el
mecanismo listo para activar con autorización explícita.

## Por qué una concesión y no un booleano

Abrir `IMPORT_GATE_ENABLED=true` durante una corrida y cerrarlo en un paso `finally` deja la
compuerta abierta si el runner se cancela, se cae la red o GitHub interrumpe el job. Un `finally`
no cubre esos casos.

La automatización usa una **concesión de un solo registro** (`import_gate_lease`) con vencimiento:

- El runner autenticado pide `open` con un TTL (por defecto 600 s, máximo 900 s).
- El gateway acepta importaciones solo mientras `expires_at` sea futuro y la fuente coincida.
- Si el runner nunca cierra, la concesión vence sola y el gateway vuelve a responder 503.
- `close` solo la puede retirar la fuente titular; otra fuente recibe 409.
- `opened_by` identifica la ejecución (`IMPORT_GATE_RUN_ID`, o ID/intento de GitHub).
  La apertura es atómica; otra ejecución recibe 409. Repetir la apertura del
  mismo titular no renueva el vencimiento ni escribe. Un `close` de una corrida
  que no adquirió la concesión no puede cerrar la de otra.
- Sin la tabla, con la tabla vacía o con la tabla inaccesible, el gateway falla cerrado.

## Flujo del workflow

1. Verifica `FDCI_IMPORT_REF` (SHA completo) y su ancestro aprobado.
2. `import-gate.mjs open` con `IMPORT_GATE_TTL_SECONDS=600`.
3. `import-via-gateway.mjs` con `FDCI_SCOPE=active`, salida a `fdci-import.json`.
4. `import-gate.mjs close` con `if: always()`.
5. Resumen con creados, actualizados, sin cambios y rechazados; sin declarar barrido completo.

El job mantiene `concurrency: fdci-import` con `cancel-in-progress: false`, `timeout-minutes: 10`
y TTL normal de 600 s. Ese TTL equivale a diez minutos desde la apertura, no
es menor que el timeout del job. El límite configurable del gateway es 900 s;
el workflow sigue solicitando 600 s. No se amplía la ventana automáticamente.

## Frecuencia inicial

`17 */2 * * *` (cada 2 horas, minuto 17): 12 corridas diarias, suficiente para ventanas de
inscripción y cambios reales de cupo. La evidencia histórica sin concesiones no
demuestra el consumo del mecanismo nuevo: autenticación y apertura/cierre agregan
operaciones. Deben consultarse los resultados canary antes de aprobar la frecuencia.
Se puede bajar a cada hora si una ventana corta lo
exige; no conviene bajarla más porque el cupo cambia por inscripciones reales y cada cambio genera
una escritura.

## Activación (requiere autorización aparte)

1. Aplicar `migrations/0031_import_gate_lease.sql` en la D1 objetivo (canary primero).
2. Desplegar `workers/source-import-gateway.mjs` con:
   - `IMPORT_GATE_LEASE_REQUIRED=true`
   - `IMPORT_GATE_ALLOWED_SOURCE=fdci`
   - `IMPORT_GATE_ENABLED=false` (la concesión es la que habilita)
   - `FDCI_EXTERNAL_ENABLED=true`
3. Cargar `FDCI_IMPORT_SECRET` como secreto del Worker y del environment de GitHub.
4. Mantener el mismo `IMPORT_GATE_RUN_ID` en apertura y cierre de una corrida;
   los pasos de GitHub ya lo fijan al ID/intento. Verificar que el commit esté **fusionado en la rama predeterminada** (los `schedule` solo
   corren ahí) y fijar `FDCI_IMPORT_REF` a ese SHA exacto.
5. Definir `FDCI_AUTOMATION_ENABLED=true` y descomentar el `schedule`.
6. Primera corrida programada: revisar resumen, `created/updated/unchanged`, y que el gateway
   responda 503 entre corridas.

## Apagado inmediato y recuperación

- Inmediato, con autorización: desplegar el gateway con `IMPORT_GATE_LEASE_REQUIRED=false`
  e `IMPORT_GATE_ENABLED=false`. No borrar tablas para apagarlo. No depende de GitHub.
- Manual: establecer el `IMPORT_GATE_RUN_ID` de la concesión y cargar el secreto
  por entrada protegida; `SYNC_SOURCE=fdci IMPORT_GATEWAY_ORIGIN=... node
  scripts/import-gate.mjs close`.
- Si una corrida falla a mitad: la concesión vence sola; el workflow igual intenta `close`.
- Si el gateway responde 503 durante la corrida: el runner falla y no reintenta solo.
- Rollback del Worker: `wrangler rollback <versión anterior>` con la configuración del gateway.

## Riesgos pendientes

- La concesión es de una sola fila: FDCI y otra fuente no pueden importar a la vez (por diseño).
- Si se filtra el secreto, un tercero podría abrir una concesión de hasta 15 minutos; el secreto
  vive solo en el environment de GitHub y en el Worker.
- El importador sigue sin reconciliar ausencias: no borra ni marca históricos.
- `sync_state` no se actualiza con estas corridas (el receptor no declara barridos completos).
- La concesión comprueba admisión al inicio de cada petición; su vencimiento no
  cancela una escritura ya admitida. No programar dos runners por fuera del
  protocolo open/import/close ni omitir el rechazo 409. Conservar lotes pequeños.
