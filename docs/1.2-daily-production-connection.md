## Persistencia y datos existentes

`daily-state-production-infd` y `daily-state-production-cenet`. Requiere la marca
sellada `environment=production`; rechaza estados Canary. Las ramas se crean solo
tras autorización. Una rama ausente produce error, nunca un reinicio silencioso.

Después de fijar el SHA ejecutable, generar cada archivo local con:

```powershell
node scripts/daily-sync-state.mjs seed-local sime <SHA_APROBADO> <ARCHIVO_NUEVO> production
```

Repetir con `infd` y `cenet`. Publicar cada archivo únicamente en su rama de estado,
como `sime.json`, `infd.json` o `cenet.json`, verificando SHA, checksum y procedencia.
No copiar confirmaciones, colas, fixtures ni registros de Canary. Sus 36 pendientes
SIME y 14 INFoD se conservan en sus ramas originales para futuros ensayos Canary;
no son una confirmación de que esas publicaciones existan en producción.

En producción, recolectar de nuevo la fuente oficial y usar los IDs estables y
upserts existentes: no truncar ni restaurar tablas, no cambiar IDs o relaciones
personales, y no sustituir la base por una exportación Canary. Los campos oficiales
solo se actualizan según los hashes del receptor existente; no se reimporta una
base completa. Los ACK se confirman antes de avanzar. Se conserva el máximo de
50 publicaciones por ejecución y el estado PARTIAL cuando queda trabajo.

`production-cenet`, restringidos a la rama predeterminada y al SHA revisado.

## Noticias: diagnóstico local, sin otra corrida

`news-feed-diagnostics.mjs` envuelve únicamente la recolección. Emite un evento
`NEWS_SOURCE_FAILURE` con fuente fija (`ministry`, `atep`, `infod`), nombre, fase,
hora inicial/final UTC y tipo: HTTP, TLS, REDIRECT, FORMAT, CONTENT, TIMEOUT,
NETWORK o UNKNOWN. En errores HTTP incluye el status. Nunca serializa mensajes,
causas, stacks, URLs, parámetros, cabeceras ni artículos completos.

La causa de la corrida 42467931919 sigue sin demostrarse: el código nuevo permite
diagnosticar una futura corrida, no reconstruir datos que el log anterior omitió.
El mismo cambio quedó aplicado localmente al runner aislado publicado en
`release/news-canary`, conservando sus concesiones. Para usarlo remotamente habrá
que publicar selectivamente el helper y el cambio de import/llamada; no fusionar
la preparación productiva sobre esa rama ni reintentar sin nueva autorización.
Al cambiar el SHA de Noticias, actualizar bajo CAS solamente la revisión aprobada,
generación y checksum de su ledger, validando primero el SHA anterior y conservando
cursor, cola, confirmaciones y suspensión. No inicializar otra vez `daily-state-news`:
la validación estricta del SHA rechaza automáticamente una revisión incompatible.

(`drive.googleapis.com`) y disponer de una API key con restricción de API

ni acceso de escritura; solo sirve para los listados de archivos que ya sean
públicos. No vuelve públicos documentos privados.

Guardar su valor manualmente en GitHub:
`possee41/docentetuc` → Settings → Environments → `canary-juntas` → Environment
secrets → `GOOGLE_DRIVE_API_KEY`. No enviarlo por chat, no guardarlo en Git y no
instalarlo en Cloudflare. El workflow existente lo entrega solamente al runner
Node de Juntas mediante `secrets.GOOGLE_DRIVE_API_KEY`; `listDrivePage` lo usa en
`x-goog-api-key`, no en la URL. Mantener los límites de 25 solicitudes y 20
intentos de publicación. No ejecutar Juntas al configurar el secreto.

No usar restricciones de referente HTTP: este es un runner de servidor. Las IP de
GitHub-hosted runners cambian; no inventar una IP fija ni contratar runners pagos.
Aplicar restricción de API y supervisar la cuota del proyecto. Si la consola exige
habilitar facturación o ampliar permisos fuera de lo autorizado, detenerse. La
clave no permite limitar su uso a una carpeta determinada; la allowlist de raíces
sigue implementada en el recolector. Padrones y Llamados permanecen pendientes.
