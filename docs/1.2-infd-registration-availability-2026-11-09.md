# INFoD: inscripción no disponible — corrección local, 09/11/2026

## Caso confirmado y alcance de lectura

La API pública de DocenteTuc identifica una capacitación con el enlace 736:

- **La enseñanza de la matemática en la transición de primaria a la secundaria: Oportunidades y desafíos**.
- ID: `infd:programa-nacional-de-fortalecimiento-de-matematica-2026-la-ensenanza-de-la-matematica-en-la-transici`.
- Estado almacenado visible en la API: **consultar**; no se afirma que este registro concreto estuviera clasificado como abierto.
- [Destino de inscripción 736](https://aulastic.infd.edu.ar/catalogo.cgi?wAccion=oferta_view&oferta_id=736): HTTP **200**, pero el bootstrap `Educativa.Aula.Catalogo.ListView` contiene `errors[].msg="La oferta no está disponible"` y otras ofertas, entre ellas 756. Esas tarjetas no corresponden a la consulta 736.
- [Página informativa del mismo curso](https://red.infd.edu.ar/programa-nacional-de-fortalecimiento-de-matematica-2026/): HTTP **200**, conserva el vínculo 736. No se encontró allí un reemplazo oficial confirmado para la misma capacitación. No se sustituyó por otra oferta.

Comprobación acotada: **3 GET oficiales instrumentados desde Node** (dos al destino 736 para confirmar su codificación y uno a la página informativa), más dos lecturas de la API pública. El primer intento con la herramienta web no devolvió contenido. No se inspeccionó todo el catálogo ni se siguieron recomendaciones. Sin acceso directo a D1 remota, sincronizaciones, cambios de credenciales ni escrituras remotas.

## Causa

El recolector extraía el enlace «INSCRIPCIÓN» de la página informativa, pero no comprobaba la respuesta de la plataforma de inscripción. La UI conservaba ese enlace aunque su destino ya no estuviera disponible, sin distinguir esa situación del estado no verificado.

AulaS-TIC devuelve un error semántico dentro de JavaScript junto con HTTP 200. Además, declara **ISO-8859-1**: una decodificación UTF-8 altera «está» y puede impedir reconocer el aviso. No hay que ejecutar JavaScript ni analizar los cursos recomendados para detectar este caso.

## Corrección implementada exclusivamente en local

- `lib/infd-registration.ts`: URL exacta permitida, lectura del bootstrap JSON sin `eval`, prioridad del aviso de indisponibilidad y rechazo del catálogo de reemplazo como evidencia de la oferta consultada.
- `scripts/infd-registration.mjs`: comprobación Node de hasta **tres GET adicionales** por invocación del recolector, caché por URL, timeout 20 s, máximo 256 KiB, decodificación de charset y redirecciones rechazadas. No utiliza cookies ni credenciales. No se habilitó en los runtimes remotos fijados por SHA.
- `scripts/import-public-sources.mjs`: integración únicamente en la rama INFoD. Error HTTP/red/formato o presupuesto agotado queda como **UNVERIFIED**, no como cerrado o retirado. Una comprobación no intentada no recibe fecha de verificación ficticia.
- Metadata existente: `registrationVerification` diferencia **OPEN, CLOSED, UNAVAILABLE y UNVERIFIED**, con URL, fecha cuando hubo intento y motivo. No requiere tablas ni migraciones.
- La inscripción abierta requiere identidad del curso/oferta y evidencia explícita de su propio formulario. Una fecha futura o una tarjeta relacionada no bastan. Una comprobación positiva caduca a las 24 horas; otra URL no puede reutilizarla.
- La UI distingue «Oferta no disponible», «Inscripción cerrada» e «Inscripción no verificada». Omite el enlace de inscripción cuando está confirmada como no disponible o cerrada y conserva el enlace informativo y el historial. Para una oferta no verificada ofrece solo «Verificar disponibilidad de la oferta».
- La clasificación de no disponible no borra el registro. Se excluye de oportunidades personales activas y de aperturas/recordatorios nuevos; no elimina datos guardados existentes. Las reglas de CeNET y FDCI se conservan.

Reproducción completamente offline con ambas páginas capturadas: mismo ID y título que la API pública, `status=oferta no disponible`, `normalizedStatus=CLOSED`, `enrollmentState=NO_DISPONIBLE`, motivo `OFFICIAL_UNAVAILABLE_NOTICE`. Cero escrituras remotas.
