## Aprobación 1: identidad y punto recuperable, solo lectura

Desde un checkout limpio del SHA aprobado, usar Wrangler instalado:

```powershell

node .\node_modules\wrangler\bin\wrangler.js d1 info docentetuc-db --config $webConfig --json

node .\node_modules\wrangler\bin\wrangler.js d1 time-travel info docentetuc-db --config $webConfig --json
```

Registrar en un archivo privado fuera del repositorio el SHA aprobado, UUID,
versión Worker, hora UTC y bookmark. Confirmar el mismo destino y que la lista
pendiente sea exactamente los siete archivos anteriores. Verificar cuenta y
bindings mediante metadatos sin volcar credenciales OAuth. Si la tabla de
migraciones no refleja el esquema, resolver esa diferencia antes de aplicar.

Time Travel ya conserva el historial: registrar el bookmark no modifica D1.
En Free la ventana documentada es **7 días**; anotar la caducidad y obtener un
bookmark nuevo inmediatamente antes de migrar. Este documento prepara el
respaldo; **todavía no contiene un bookmark productivo nuevo**.

## Rollback y restauración

Rollback normal: cerrar gateway, impedir nuevos jobs, esperar y comprobar el
fin de Node y de las solicitudes gateway en curso. Si se habilitaron fuentes de
eventos, deshabilitar únicamente sus filas de control con autorización, conservando
eventos y publicaciones. Recién entonces restaurar el Worker 1.1 registrado:

```powershell
node .\node_modules\wrangler\bin\wrangler.js rollback 3ac6a189-ad4a-463e-b97c-814766c25fb8 --config $webConfig
```

No usar `858a154e`: perdería la mejora de carga privada. Confirmar disponibilidad
del ID antes del lanzamiento. El Cron conservado vuelve a ejecutar el código
1.1 y sus tareas originales; por eso ningún escritor externo puede seguir activo.
Las tablas e índices aditivos permanecen. Noticias 1.2 no será visible en 1.1,
pero no se borra. El rollback del Worker no restaura D1 ni necesariamente cambia
rutas o Cron: comprobar los metadatos registrados. La evidencia local cubre
lecturas y escrituras representativas, no una restauración productiva ensayada.

Restaurar D1 solo ante daño de datos confirmado y autorización específica:
detener escrituras de importadores **y de la aplicación**, registrar un bookmark
del estado previo a restaurar y evaluar las escrituras que se perderían. Si no
se puede garantizar mantenimiento sin escrituras, no ejecutar la restauración.

```powershell
$restoreBookmark = Read-Host 'Bookmark anterior a migraciones, verificado y vigente'
node .\node_modules\wrangler\bin\wrangler.js d1 time-travel restore docentetuc-db --config $webConfig --bookmark $restoreBookmark
```

La restauración sobrescribe D1 y cancela consultas en curso. Verificar después
esquema, integridad y acceso 1.1 antes de reabrir escrituras. Conservar también el
bookmark de deshacer devuelto por Cloudflare. No ejecutar una restauración como
parte automática del rollback web.
