# FDCI: despliegue cerrado detenido antes de intervenir

Base: `f5167ae`, rama `feat/1.2-sync-integration`. Se leyó AGENTS.md y se preservaron todos los cambios ajenos. No se modificó código funcional ni configuración, no se accedió a Cloudflare y no se desplegó ningún Worker.

## Impedimento demostrado

La autorización exige simultáneamente:

```text
IMPORT_GATE_ENABLED=false
IMPORT_GATE_LEASE_REQUIRED=true
IMPORT_GATE_ALLOWED_SOURCE=fdci
```

y que el gateway permanezca completamente cerrado, incluso frente a intentos de abrir concesiones, devolviendo 503 sin consultas D1 innecesarias. **El código validado no asigna ese significado a esta combinación.**

En `workers/source-import-gateway.mjs`:

- `handleLease` admite el procesamiento de aperturas cuando el modo lease está activo. No utiliza IMPORT_GATE_ENABLED=false como interruptor de esas aperturas. Una solicitud autorizada puede crear la concesión después de comprobar identidad y propietario.
- La condición de cierre de las rutas de importación es `IMPORT_GATE_ENABLED !== "true" && !leaseMode(env)`. Con LEASE_REQUIRED=true no se cumple; una petición sin autorización llega a autenticación y devuelve 401, no 503.
- `FDCI_EXTERNAL_ENABLED=false` protege el receptor de publicaciones, pero no deshabilita la ruta de concesión ni constituye un cierre general de las operaciones del gateway.

No se afirma que exista una credencial FDCI productiva ni una apertura indebida real. La ausencia de ese secreto evita autenticación válida, pero no cambia la semántica de los flags ni satisface la comprobación 503 solicitada. No se utilizaron secretos productivos para demostrar el problema.

## Verificación focalizada exclusivamente local

Se invocó el módulo real del gateway en Node, con Requests en memoria, identidad ficticia, secreto sintético y adaptador D1 falso. Ninguna petición de red y ninguna escritura D1 real. No se intentó abrir una concesión en producción o canary.

| ENABLED | LEASE_REQUIRED | Escenario local | HTTP | Llamadas D1 simuladas |
|---|---|---|---:|---:|
| false | true | Importación sin autorización | 401 | 0 |
| false | true | Apertura con secreto sintético válido | 200 | 3, incluida tentativa de INSERT simulada |
| false | false | Importación sin autorización | 503 | 0 |
| false | false | Apertura con secreto sintético válido | 503 | 0 |

Las aserciones pasaron. No es una nueva campaña canary ni una regresión detectada: coincide con el comportamiento de concesiones ya validado. Evidencia sin credenciales: [prueba local de flags](evidence/2026-11-01-fdci-closed-flags-local.json).

## Alternativa mínima, pendiente de autorización

Para el despliegue inicialmente cerrado, reutilizar el interruptor existente sin cambiar código:

```text
IMPORT_GATE_ENABLED=false
IMPORT_GATE_LEASE_REQUIRED=false
IMPORT_GATE_ALLOWED_SOURCE=fdci
FDCI_EXTERNAL_ENABLED=false
```

Preservar binding e identidad productivos, secreto SIME y demás parámetros; no configurar secreto FDCI. Ambos flags false bloquean importaciones y aperturas antes de autenticar o consultar D1. Activar el modo lease corresponde al piloto posterior con autorización específica, no al despliegue cerrado.

Esta propuesta difiere del LEASE_REQUIRED=true obligatorio del pedido actual, por lo que **no se aplicó**. No hace falta introducir otro flag, cambiar las garantías de concesión ni modificar el código validado para conseguir el cierre.
