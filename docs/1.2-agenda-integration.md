# Agenda: integración y aviso de recuperación

Base: `aa120af`, rama `feat/1.2-sync-integration`. Trabajo exclusivamente local.

## Causa reproducida

`/api/installations/credential` puede responder `409 recovery_required` cuando falta
la prueba del dispositivo. Eso no descarta una sesión de cuenta válida: el resolver
del backend comprueba también esa cuenta para autorizar `/api/app`.

La interfaz anterior marcaba el bootstrap terminado antes de esperar esa segunda
respuesta. En la aplicación completa, con el 409 seguido de un 200 demorado,
el observador del DOM registró el aviso de recuperación una vez y luego Agenda.
Con la corrección, la misma secuencia registra cero avisos de recuperación.
Esto reproduce la causa localmente; no se inspeccionaron solicitudes productivas.

## Corrección

- Estados de acceso: comprobando, autorizado, rechazado y fallo de servicio.
- La recuperación se anuncia solamente después del rechazo de la API privada
  y de la respuesta de instalación que exige recuperación.
- Un error temporal no se presenta como recuperación. Los reintentos vuelven al
  estado de comprobación; una recarga con datos ya autorizados conserva la vista.
- No cambiaron endpoints, autorización del backend, vinculación, esquema ni SQL.
- En Agenda móvil, campos desplazables y acciones siempre visibles; superficie
  opaca para evitar que el contenido situado detrás dificulte la lectura.
