# FDCI Canary: aislamiento por cuenta y fixture privado (2026-11-07)

Base: `725a4bf`. Trabajo local; ninguna escritura, despliegue ni prueba funcional remota. No se alteraron autenticación/OAuth, consultas públicas, Noticias, Administración, GitHub Actions, catálogos GitHub ni el gateway HALTED.

## Resultado implementado

- Lista privada de **un ID estable de cuenta**. La sesión se valida con `getAuthenticatedAccount`; además, `currentUser.userId` debe coincidir. Una instalación sin cuenta autenticada, una URL o un header con userId no autorizan la prueba.
- Se exige `FDCI_CANARY_TEST_ENVIRONMENT=docentetuc-web-canary-1-2` y host Canary exacto (localhost solo para pruebas locales). Producción permanece excluida incluso copiando flags.
- Único fixture `fdci:canary-personal:1`, título FICTICIA, `preview=true`, `catalogOnly=true`, origen `fdci-canary-fixture`, run ID y propietario. No tiene URL de inscripción. Es independiente del lector y checksum oficial; no se descarga ni modifica el catálogo oficial para usarlo.
- Lectura a través del GET privado existente `/api/app?fdciPersonalFixture=1`, solo para la cuenta autorizada. El cliente lo muestra únicamente en modo experimental de Capacitaciones, fuera del catálogo público. Guardados/Agenda conservan sus relaciones habituales. Las consultas públicas existentes ya excluyen sus marcas; no se cambiaron.
- Todas las mutaciones del fixture, incluidas cancelación y limpieza, verifican la identidad antes de escribir. Se rechazan las variantes con espacios en IDs antes de saltar a las ramas normales. Las acciones sobre otros snapshots FDCI externos también aplican la lista, incluida su retirada; los cursos D1 ordinarios conservan el comportamiento anterior.
- Ventana de acceso máxima de 30 minutos; apertura simulada al menos 24 horas después. No se generan avisos automáticos del fixture: la regla compartida del materializador excluye `fdciCanaryFixture=true` y no se admite un recordatorio de entrega para Agenda en este fixture.
- Limpieza privada mediante acción `cleanup_fdci_canary_fixture` en el POST existente. Verifica ID, propietario, run configurado, metadata y hash; rechaza referencias de otros usuarios. El batch borra únicamente relaciones del propietario para ese ID y esa publicación. Cambios concurrentes o fallos SQL no eliminan datos ajenos. Puede ejecutarse por el mismo propietario tras el vencimiento y con los flags de alta cerrados; no permite crear ni reactivar nada. Nunca borra perfiles, sesiones o cuentas.
