## Código ejecutable

- `scripts/daily-sync-state.mjs`: progreso público durable en Git Contents API. Rama fija `daily-state-<fuente>` y archivo `<fuente>.json`, en `possee41/docentetuc`. Checksum SHA-256 del estado, SHA Git del blob, procedencia, SHA ejecutable, generación y CAS contra la revisión anterior. La rama no caduca como un artifact. Falta de rama, archivo corrupto o cambio de ejecutable detienen; nunca inicializan ni reinician automáticamente.
- Cada corrida reclama el estado mediante CAS. Cada publicación registra intención antes del HTTP y confirma hash/cursor después de un ACK completo. Cola de filas públicas pendiente, sin credenciales ni usuarios; una observación completa más reciente reemplaza la versión pendiente anterior. Confirmados sin cambios no vuelven a enviarse. Si el Git ACK se pierde, una lectura verifica el blob propuesto, sin repetir el PUT. Si el ACK del receptor se pierde, queda inFlight/HALTED: no reintentar en automático. Requiere reconciliación de solo lectura y recuperación expresamente autorizada. Un fallo/cancelación no pierde la cola; un proceso nuevo restaura el mismo estado.
- `scripts/daily-sources.mjs`: reutiliza `runSimeImport`, `runPublicSourceImport` y los checkpoints Juntas. SIME/INFoD/CeNET primero completan y validan la recolección en Node con un receptor de staging en memoria. No envían una sola publicación al servidor si la fuente queda incompleta. Después persisten hasta **50 filas** por corrida, una por HTTP, conservando los límites existentes de SIME y del receptor. El último éxito solo avanza con cola vacía y finish confirmado; mientras tanto, sync_state queda PARTIAL. No se eliminan por ausencia registros que no están en una colección. Los datos previos no se sustituyen por un catálogo parcial definitivo.
- Juntas conserva su cursor/lease/confirmaciones D1 por raíz, 25 solicitudes y 20 intentos de publicación. Se añade bloqueo/suspensión Git por corrida; no se modifica el algoritmo de checkpoint. Incluye Padrones, Comunicados y Llamados, no jobs duplicados.
- `scripts/news-via-receiver.mjs`: recolecta los tres feeds `NEWS_FEEDS` (Ministerio, ATEP e INFoD) en Node, envía `articles[]` al endpoint existente, valida HTTP y ACK y mantiene cola durable. Máximo **5 artículos** por corrida, uno por request; los demás se conservan. El endpoint mantiene validación de feed/hostname, secreto y transacción; la restricción temporal solo-INFoD se reemplazó por el registro existente de tres feeds. Desconocidos y enlaces de otros hosts siguen rechazados. No cambia el panel editorial ni publica/aprueba/archiva; las ediciones manuales de noticias publicadas se conservan. LastSuccess por este runner queda en Git; no se inventa un campo nuevo de salud en la UI.
- `workers/daily-source-gateway.mjs` y `wrangler.1.2-daily-sources.jsonc`: destino separado **docentetuc-sources-1-2**, no el viejo Worker FDCI. Reutiliza autenticación, identidad y concesiones de los receivers existentes; rechaza toda ruta/fuente FDCI, no admite TTL mayor a 600 segundos y sale antes de D1 si está deshabilitado. Configuración local sin rutas, previews, workers.dev, Cron o secretos; DAILY_SOURCES_ENABLED=false. Node reclama estado antes de abrir una concesión, propaga propietario, y cierra en finally. TTL es la barrera independiente ante cancelación de GitHub; si el cierre no se verifica, Git suspende la fuente. La apertura no se renueva automáticamente durante la corrida. No se modificó el gateway FDCI ni sus settings.

## Límites reales

Implementación local funcional, no activación ni prueba remota. D1 conserva incrementos ya confirmados y estado PARTIAL hasta completar persistencia, no una transacción global de todo el catálogo. Git y D1 no son una transacción distribuida: las intenciones previas y la suspensión resuelven la ambigüedad sin ocultarla. Después de una restauración o edición externa de D1 que invalide confirmaciones, detener y reconciliar el ledger antes de reanudar.

La cola y los controles añaden requests/commits Git y escrituras legítimas de salud/checkpoints; pueden alcanzar rate limits o TTL con lotes grandes. No se amplía el presupuesto automáticamente. La política es una corrida diaria, no garantía de frescura menor a 24 h para catálogos extensos o ráfagas. Juntas mantiene 20 intentos y FDCI su techo vigente. Ninguna medición local certifica los 10 ms de Workers Free. Persistencia, acceso al receptor independiente, permisos Git y CPU remota siguen siendo condiciones reales de activación, no excusas para repetir el gateway FDCI antiguo.
