## Evidencia obligatoria por petición

| Dato | Comprobación |
|---|---|
| Worker y versión completa | Coinciden con deployment registrado; la versión efectiva figura en el evento |
| Identidad de invocación | ID único del evento/request y correlación inequívoca con petición prevista |
| UTC, método y ruta | Coinciden con manifest; sin queries sensibles |
| HTTP y `outcome` | Valores explícitos y esperados; el control cerrado es 503 con ejecución `ok` |
| `cpuTimeMs` | Número individual finito, no negativo, <=7 ms |
| `wallTimeMs` | Campo separado, opcional; nunca sustituto de CPU |
| Errores | Sin `exceededCpu`, 1102, excepciones o errores D1 |

Conservar los nombres originales de los campos exportados y su correspondencia
con estas columnas (por ejemplo, `cpuTimeMs`, `scriptVersion.id`, `requestId` y
`outcome` dentro del contenedor que entregue Cloudflare). No inventar campos ni
asumir que Ray ID = request ID. Una coincidencia solo por horario no demuestra
identidad. Si el evento no contiene versión/ruta/CPU identificables, rechazar.

En una futura corrida, conciliar **cada petición**, incluidas identidad, concesión,
importación, checkpoint, reporte y cierre. Exigir exactamente un evento verificable
por petición esperada, sin exportación truncada. No cubrir el último reporte con
un hook que se ejecuta antes de ese reporte. Campos ausentes, eventos faltantes,
duplicados contradictorios, CPU >7 ms o 1102 mantienen la suspensión y prohíben
nuevas corridas. No se alteran el umbral, el latch persistente ni sus condiciones
de recuperación. p99 no es máximo individual; tiempos Node/Workerd no son CPU remota.
