# FDCI: persistencia sintética entre GitHub Actions

Base `55c7033`, rama `feat/1.2-sync-integration`. Solo implementación/pruebas locales. Sin acceso a D1, gateway, Cloudflare, fuentes oficiales, GitHub API ni Pages. Lectura visual ya aceptada por el propietario: no repetida. Cambios ajenos conservados.

## Correcciones concretas

- El selector anterior descartaba artifacts vencidos antes de seleccionar, pudiendo retroceder a uno más antiguo. Ahora identifica primero la última corrida completada del mismo workflow/rama/SHA. Si su artifact falta, está duplicado, caducó o tiene metadatos incompatibles, detiene la recuperación. También rechaza re-runs, forks y eventos ajenos a `workflow_dispatch`.
- Manifest v2 con SHA-256 de checkpoint, catálogo y procedencia: repositorio, workflow, corrida, intento, SHA aprobado, rama y dataset `synthetic`. Restauración exige coincidencia con la selección obtenida mediante API. Es integridad y procedencia dentro del repositorio de confianza, no firma contra un administrador malicioso.
- Descarga por **ID exacto** de artifact y corrida, con paginación de inventarios. Validación completa antes de crear el destino y promoción mediante rename de un directorio nuevo; no sobrescribe un estado existente.
- Namespace exclusivo `fdci-static-synthetic-state-v2`, separado de los datos reales y del piloto público de dos registros. No convierte artifacts v1 automáticamente.
- El piloto anterior completaba dos registros en un job. Ahora usa seis cursos ficticios: obliga a conservar progreso y terminar en otro runner. Los GET/POST del recolector se resuelven en memoria, sin contactar la API oficial.

## Persistencia y fallos

Cada corrida restaura `private/checkpoint.json` y el último `public/catalog.json` completo. Tras recolectar, exporta solo un snapshot validado y lo sube como artifact inmutable; el ID queda en el resumen. El disco temporal no es la persistencia entre jobs.

Retención solicitada: **dos días**, verificada también contra `expires_at` real. Máximo 8 MB por snapshot. Esto sirve para un piloto finito, no constituye almacenamiento permanente ni una copia de seguridad. Si el artifact de la última corrida falta/caducó/corrompió, se detiene incluso si existe uno anterior. Hace falta recuperación revisada desde una copia íntegra; nunca reset automático. `bootstrap=true` solo admite la primera corrida sin antecedentes de ese SHA/rama/workflow. Cambiar el SHA requiere un traspaso revisado; no implica heredar estado de código no aprobado.

Un error antes del commit local conserva checkpoint y catálogo anteriores. La exportación se intenta aun si falla la recolección, y puede conservar ese estado confirmado. Una cancelación abrupta puede impedir la subida: el siguiente job quedará bloqueado por artifact faltante. No se promete recuperación automática de un estado que nunca llegó al almacenamiento remoto.

`concurrency` compartida con `cancel-in-progress:false` evita dos jobs activos; `.cycle.lock` impide doble escritor local. No se garantiza orden FIFO de todos los pendientes: el piloto debe despacharse secuencialmente, comprobando que la corrida previa terminó. Re-runs deshabilitados mediante `run_attempt == 1`.

## Barrera contra catálogo parcial

Con seis solicitudes se consultan los dos listados y cuatro detalles: se guarda cursor, quedan dos pendientes y **no se genera catálogo público**. El segundo job recupera el artifact, solicita los dos listados y dos detalles restantes y valida seis IDs únicos antes de completar.

Un catálogo completo anterior permanece byte a byte durante errores, interrupciones o avances parciales. Solo se crea el artifact `fdci-static-synthetic-complete-v2` si el recolector terminó con `status=complete`, `published=true` y la subida del estado durable tuvo éxito. Este workflow **no publica Pages**, carece de permisos para hacerlo y no cambia el JSON público vigente. Publicación real futura requiere otra autorización.

## Resultado local

**7 pruebas focalizadas aprobadas**, ESLint de los dos scripts correcto, YAML parseado y seis bloques Bash verificados con `bash -n` (sin ejecutar sus comandos).

- Tres pruebas de artifacts/workflow: procesos Node distintos, directorios nuevos, transferencia con procedencia, interrupción en otro proceso sin avance, reanudación, restauración de catálogo completo, checksums, rechazo de campos extra, IDs/repositorio/SHA/rama/intento, caducidad/missing/duplicación y permisos/disparadores del workflow.
- Cuatro escenarios relevantes del ciclo existente: seis solicitudes/interrupción sin perder catálogo, cambio de composición sin publicación parcial, fechas de comprobación frente a cambio efectivo y dos recolectores concurrentes.
- Resultado medido: primer proceso `partial`, 6 solicitudes simuladas, 4/6 cursos; siguiente proceso `complete`, 4 solicitudes simuladas, 6/6 cursos. IDs sin duplicados, checksum determinista al invertir orden de entrada y fechas por registro conservadas. Sin medición de CPU remota ni afirmación de ejecución real en GitHub.

Reproducción:

```powershell
node --experimental-strip-types --test scripts/fdci-static-artifact.test.mjs
```
