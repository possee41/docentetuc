# FDCI personal: E2E local — 2026-11-07

Resultado: Guardados, Agenda y alta/cancelación de recordatorios APTOS en el entorno local aislado. No demuestra entrega automática ni CPU de Cloudflare.

## Cambios

- Cliente y servidor comparten el lector oficial `fdci-catalog/active.json`, generación, versión inmutable y checksum. El servidor no acepta un DTO de publicación enviado por el cliente ni el antiguo catálogo DEMO.
- Materialización `catalogOnly` + relación personal en un batch transaccional. Sin nuevas tablas/migraciones, sin UPDATE sobre publicaciones existentes. Hash esperado protege las escrituras personales frente a modificaciones concurrentes.
- Una modificación o retiro de la fuente bloquea nuevas acciones con 409 y conserva el snapshot y las relaciones del propietario. Cancelar avisos y retirar Guardados/Agenda continúa disponible sin catálogo ni flag activo. No se migra silenciosamente el snapshot a otra versión.
- Una generación nueva con el mismo contenido renueva la prueba del cliente, sin sobrescribir el snapshot D1. Las consultas públicas aprobadas no se modificaron.
- `FDCI_PERSONAL_ACTIONS_ENABLED=true` permite la prueba solamente en localhost/127.0.0.1/Canary. Ausencia o false mantiene cerrado el servidor. La UI experimental consume esta capacidad y no habilita acciones para snapshots sin verificación.
- Contrato opcional schema 3: evidencia de trainingId, precisión horaria, estado confirmado y cupo protegida por checksum. Schema 1/2 continúa siendo válido para lectura, Guardados y Agenda; nunca se inventa precisión para activar avisos. El publicador oficial deberá conservar esa evidencia antes de ofrecer avisos de apertura reales. No se modificó el recolector ni su publicación remota.

## Rendimiento y límites

Una muestra local, no CPU remota: primer guardado 18,245 ms wall/5 sentencias SQL/2 GET de catálogo; repetición 0,583 ms/4 sentencias/0 GET; aviso 13,474 ms/4 sentencias/0 GET. Estos tiempos incluyen Node/SQLite y no prueban el límite de Workers Free. SQLite no ofrece aquí filas D1 leídas ni CPU Worker; no se infieren.

El servidor comparte la descarga pendiente, retiene 60 segundos un snapshot validado y rechaza versiones mayores a 128 KiB. La validación fría y las reglas de fechas todavía pueden superar el presupuesto remoto; medir cold/warm antes de habilitar. Ante resultado ambiguo, la UI recarga por lectura sin repetir la mutación.
