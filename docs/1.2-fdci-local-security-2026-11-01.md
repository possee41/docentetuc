## Correcciones

| Bloqueo | Solución local |
|---|---|
| Destino productivo incompleto | Variables explícitas de destino/habilitación/SHA. FDCI_IMPORT_REF debe coincidir exactamente con FDCI_IMPORT_APPROVED_SHA y con HEAD. Preflight valida configuración, propietario, presupuestos e identidad antes de open. Un checkout antiguo que desconoce preflight/run falla cerrado. |
| Propietario no comprobado al importar | Encabezado x-import-gate-owner obligatorio en modo lease. El gateway compara propietario, fuente y expiración. La escritura FDCI incluye EXISTS sobre la concesión dentro del UPSERT: también protege contra cambio de dueño/expiración entre admisión y escritura. |
| Ejecutor sin límites del canary | El runner habitual usa active, máximo seis solicitudes oficiales contando reintentos, pausas mínimas 400 ms, timeout 20 s y máximo cinco intentos de publicación; una publicación por petición. Valores ampliados o inválidos se rechazan. |
| Históricos fuera de alcance | Se omiten 6375, UNKNOWN y cursos genéricos. En modo lease, el receptor también rechaza esos contenidos y protege filas existentes UNKNOWN, incluso ante cambios entre lectura y escritura. No hay reconciliación de ausencias ni cambios en sync_state. |
| Fuente inválida/JSON no acotado | Validación de propiedad propia y tipo string; fuentes heredadas devuelven 400. El cuerpo de control se limita realmente a 1.024 bytes, aunque falte Content-Length; JSON inválido/formato incorrecto generan respuestas controladas. |
| Reintentos y resultados parciales | Las lecturas pueden reintentarse dentro del mismo presupuesto; 429 detiene el recorrido. Las escrituras no se reintentan ante pérdida de respuesta, 5xx o ACK inválido. Se registran contadores confirmados, resultado incierto, exclusiones, diferidos y razones seguras de rechazo/error. |
| Limpieza y cancelaciones | El runner existente incorpora run con finally y manejo SIGINT/SIGTERM; conserva close de respaldo con always en Actions. Cierre por propietario, incluso después de open ambiguo. Un fallo de close queda explícito; TTL sigue siendo respaldo ante muerte abrupta. |
| Resúmenes incompletos | OK/PARTIAL/ERROR, rejected numérico y demás contadores. El resumen tolera JSON vacío/ausente sin fallar de nuevo y registra el cierre de respaldo. No imprime cuerpos remotos, URLs privadas, configuración ni credenciales. |

## Migraciones y riesgos pendientes

- **No hay migración adicional.** Se reutiliza exclusivamente 0031 para la concesión. No se aplicó ninguna migración local persistente ni remota; la prueba efímera usa su SQL real.
- La validación SQL del propietario usa la misma consulta de escritura, sin añadir un cruce D1; su predicado puede aumentar lecturas/CPU. Medir canary antes de aceptar el umbral preventivo de 7 ms.
- Los clientes que usen modo lease deben enviar el nuevo encabezado. No habilitar ese modo a SIME/Juntas con sus runners actuales: sus pruebas sin lease siguen pasando y sus workflows no se modificaron.
- La concesión identifica una ejecución; no protege frente al robo del secreto por alguien que además suplante ese identificador. Mantener secretos exclusivos, entorno protegido y referencias aprobadas. No se consultaron ni modificaron secretos remotos.
- El servidor conserva TTL máximo 900 s; el runner limita su petición a 600 s. Una muerte abrupta puede impedir el cierre explícito; ninguna afirmación de finally garantiza cierre tras SIGKILL. La expiración y el fencing son respaldos.
- El máximo de seis solicitudes/cinco publicaciones limita el alcance. Un catálogo activo mayor devuelve PARTIAL; no se agregó cursor ni se garantiza cubrir los elementos finales repitiendo siempre el mismo lote. No aprobar cobertura automática completa si se alcanza el techo.
- La configuración productiva y los workflows remotos siguen como estaban. Desactivación remota de variantes antiguas, publicación, piloto, migración/despliegue y cron requieren aprobaciones futuras individuales.

**Siguiente paso:** solicitar autorización para una nueva validación canary focalizada del protocolo corregido y CPU/D1. No desplegar ni activar producción automáticamente.
