## Causa exacta y alcance

`/api/public-app` filtraba `metadata.preview` y `metadata.catalogOnly`, pero `/api/search` utiliza otras consultas: `publicationSearchQuery` para texto/secciones/paginación y `PUBLICATION_BY_ID_SQL` para ID. Ambas solo excluían los cinco IDs de ensayo. Por eso `preview:training`, con `{"preview":true}`, seguía devolviéndose por listado y acceso directo.

La revisión se limitó a lecturas que exponen publicaciones: carga inicial, búsqueda, coincidencias, Juntas/Padrones y recuperación pública de IA. No se auditó el recolector ni la infraestructura. Las consultas personales/administrativas y las publicaciones editoriales de Noticias tienen autorización o aprobación editorial independientes; no se les impuso el filtro del catálogo público.

## Una regla compartida

`lib/publication-visibility.ts` concentra el predicado SQL y su equivalente de presentación:

- Excluye los cinco IDs sintéticos previamente verificados, sin añadir IDs/rangos nuevos.
- Excluye marcas `preview` o `catalogOnly` con valor **true, 1, "true" o "1"**. No usa coerción general de valores verdaderos.
- Metadata NULL, vacía, inválida, primitiva o sin campos de control permanece admitida. CASE impide evaluar JSON inválido. Las reglas específicas de sección, alias, fechas y estados se conservan.
- No inspecciona títulos. Un curso legítimo puede contener PRUEBA, DEMO o SINTÉTICA. El lector FDCI también deja de usar la heurística por palabras: conserva el rechazo del fingerprint exacto del piloto antiguo, además de checksums, versiones, origen y rutas permitidas.

La regla se aplica **antes de LIMIT/paginación** en:

| Superficie | Consulta compartida/corregida |
| --- | --- |
| `/api/public-app` — Inicio/Capacitaciones/selección inicial | APP_PUBLICATIONS_QUERY |
| `/api/search` — texto, sección y acceso por ID | publicationSearchQuery / PUBLICATION_BY_ID_SQL |
| `/api/personalized` — descubrimiento de coincidencias | PERSONAL_CATALOG_SQL |
| `/api/boards`, `/api/boards/padrones` | boardPageQuery; también PADRON_PAGE_QUERY y filtros locales de Juntas |
| `/api/ai/chat` — candidatos públicos y foco público | retrieveAIRecords; se conserva la lectura de Agenda autorizada por user_id |

Inicio, listas y fuentes de Juntas utilizan el mismo predicado JavaScript cuando hay publicaciones privadas combinadas. Guardados/Agenda y las referencias privadas no se borran ni filtran globalmente. Administración conserva sus consultas y puede gestionar registros marcados; sus guardas de acceso no cambian.

El compositor FDCI elimina filas D1 no públicas antes de mostrar resultados. La proyección del feed versionado validado continúa disponible **solo en modo experimental**, con identidad de generación/checksum y acciones privadas deshabilitadas. No se habilitó ningún flujo personal externo ni se conectó el feed al chat. El catálogo oficial vacío sigue siendo válido y conserva los dos cursos D1 oficiales.
