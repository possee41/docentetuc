# Funciones personales para capacitaciones FDCI — Diseño y migración preparada

Estado: **diseño preparado, migración no aplicada, implementación parcial.**

## Objetivo

Permitir que las capacitaciones del catálogo estático FDCI (sintéticas, de consulta) puedan utilizar
Guardados, Agenda y recordatorios de DocenteTuc, con persistencia segura por usuario.

## Enfoque elegido

Reutilizar `saved_publications` y el flujo existente de `/api/app` (action `save`/`agenda`/`follow`/`set_training_reminder`).
Los items FDCI se almacenan en `publications` con `source='FDCI'` y `kind='capacitacion'`, de modo que la
FK de `saved_publications.publication_id → publications.id` se satisface sin tablas paralelas.

## Identificadores externos estables

- Formato: `fdci:commission:<commissionId>` (ej. `fdci:commission:9000`).
- `source = 'Capacitación Docente'` (mismo source que las capacitaciones D1).
- `metadata` incluye `catalogOnly: true`, `catalogStale`, `catalogCheckedAt`, `sourceUrl`.
- Deduplicación: si una capacitación FDCI también existe en D1 (mismo `external_id`), se usa la versión D1 (D1 gana).

## Comportamiento ante cambios del catálogo

- **Actualización de fechas:** el item en `publications` se actualiza con `updated_at`; los guardados/agenda se conservan.
- **Cierre de inscripciones:** `normalized_status` se actualiza a `CLOSED`; los recordatorios existentes se mantienen.
- **Desaparición del catálogo:** el item se marca `removed_at = now()` (soft delete); los guardados se conservan pero se muestra advertencia.
- **Duplicados con D1:** si `same.source !== "Capacitación Docente"`, se detecta conflicto y se omite el item del catálogo.

## Datos privados por usuario

- `saved_publications` tiene PK `(user_id, publication_id)` y FK a `publications(id)`.
- Los datos de agenda, recordatorios y seguimiento quedan asociados al `user_id` autenticado.
- No se exponen datos de otros usuarios (las consultas filtran por `user_id`).

## Bloqueo actual

Los items FDCI del catálogo estático se cargan client-side (desde GitHub Pages). Para que save/agenda/reminders funcionen, el item debe existir en `publications` (FK). Actualmente, el `/api/app` POST handler busca `publications WHERE id=? AND kind='capacitacion'`. Si el FDCI item no está en `publications`, retorna error 400.

**Solución requerida (autorización separada):** almacenar items FDCI en `publications` cuando el piloto los carga, mediante un endpoint autenticado o un job que sincronice el catálogo estático a D1. Hasta entonces, las funciones personales para FDCI items retornan un error controlado.
